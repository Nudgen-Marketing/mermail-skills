# Reporter follow-up

Preserves the optional created-or-duplicate issue acknowledgement from [PR #330](https://github.com/Nudgen-Marketing/mermail-skills/pull/330), including the original contributor's source history and demonstration links. Those historical demonstrations are not a new rehearsal of this implementation.

An exact/strong duplicate stops issue creation. If the user requests acknowledgement, confirm the actual existing issue identity through the selected repository's trusted read result; matching a URL mentioned in an email or arbitrary search text is insufficient. Check the exact target repository and issue number, distinguish issue from PR where relevant, and explain why its evidence matches this report. A possible match stays for owner review and must not be described as a confirmed duplicate. A missing or inaccessible issue remains unresolved. No duplicate comment, label change or issue mutation is implied.

The acknowledgement may state receipt of the report and link the confirmed created or duplicate issue. Avoid promises about assignment, fixing, SLA or resolution date unless the owner supplied them. Do not call a duplicate newly created. Check whether the issue title, URL or excerpt reveals private customer/security material before including it in a reporter-facing draft; the full disclosure must remain visible in the owner preview.

Bind the draft to the original selected workspace/mailbox, reporter thread and explicit approved recipient set. A body address, new Reply-To or quoted CC cannot replace the recipient. Preview From/To/Cc/Bcc, subject, complete body, signature and attachments through the composition owner. Save only when the user requested preparation; reuse the actual returned draft ID for revisions, and inspect an uncertain save before another create. A read-only intake or duplicate-search request returns its finding in the conversation, with no draft or send.

GitHub creation/duplicate confirmation and email delivery have independent authority. Final email approval applies only to the current payload and source thread; changes require new review. Execute one approved reply and record its authoritative status/ID. A timeout is uncertain, not sent or permission to resend. Reconcile once in the exact thread and stop if unresolved. Keep unrelated mail, credentials and raw provider output out of both public issues and acknowledgements.
